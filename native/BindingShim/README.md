# LeviLamina BindingShim

The native side of the LeviLamina binding: it includes the LL/Bedrock headers and projects the selected declarations into the C ABI described in ADR-0004.

## Target

- Windows x64 only, matching upstream LeviLamina's release/CI support.
- Built with the LeviLamina ecosystem: xmake, clang-cl, MSVC STL, `/MD`, C++20/23 as required by the headers.
- Linked against LLAPI; MCAPI symbols follow LeviLamina's own symbol toolchain (`symbolprovider` / `prelink` / `bedrockdata`).
- The C ABI is a set of versioned entry points returning per-module function tables. No CLR hosting, no HostingShim responsibilities, no C++ exceptions crossing the boundary.

## Planned layout

```
generated/
  tables/        function-table declarations and stable ordering
  shim/          extern "C" implementations
  directors/     C++ directors for managed overrides
include/         generated public headers for the shim
src/             hand-written glue (error boundary, table registry)
```

Generated sources are committed and regenerated by `Hosihikari/Bindings.Generator`; the CI diff check lives in the binding repository.

## Status

Scaffold. The build target, table generation, and director emission are not implemented yet. The first generated slice will cover LLAPI plus the reachable MCAPI closure.
